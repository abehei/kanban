# タスク説明のインライン編集

## 背景

タスク作成後に説明（description）を追加・編集する手段が TaskDetail パネルに存在しない。
説明が空のタスクではエリア自体が非表示になるため、後から説明を追記することができない。
人間とエージェントの双方がタスクの背景・意図を共有するために、作成後でも説明を編集できる必要がある。

## 対象範囲

### やること (In scope)

- TaskDetail パネルの説明エリアをクリック（またはタップ）すると編集モードに切り替わる
- 説明が空（または未入力）のタスクでも「説明を追加...」というプレースホルダーを常時表示し、クリックで編集開始できる
- 編集中は複数行入力可能なテキストエリアを表示する
- 「保存」ボタン押下または Ctrl+Enter キーで確定し、`PATCH /api/tasks/:id` へ `description` を送信する
- 「キャンセル」ボタン押下または Escape キーで編集を破棄し、元の値に戻す
- 保存成功後は `onTaskUpdated` コールバックを呼び出してパネルの表示を更新する
- 保存中はテキストエリアと保存・キャンセルボタンを disabled にする
- 保存に失敗した場合はエラーメッセージをエリア内に表示する

### やらないこと (Out of scope)

- Markdown レンダリング（表示はプレーンテキスト）
- 自動保存（フォーカスアウト時の自動保存）
- `PATCH /api/tasks/:id` エンドポイント・`taskApi.update()` の変更（既存のまま利用）
- サブタスクの description 編集（別タスクとして扱う）

## 受け入れ基準

- **AC-1**: Given 説明が空のタスクの TaskDetail を開いたとき、When 説明エリアを表示したとき、Then 「説明を追加...」というプレースホルダーテキストがクリック可能な要素として表示される

- **AC-2**: Given 説明が空のタスクの TaskDetail を開いたとき、When プレースホルダーエリアをクリックしたとき、Then テキストエリアが表示されてフォーカスが当たり、テキストエリアは空の状態である

- **AC-3**: Given 説明が入力済みのタスクの TaskDetail を開いたとき、When 説明テキストをクリックしたとき、Then テキストエリアが表示されてフォーカスが当たり、既存の説明文が入力値として設定されている

- **AC-4**: Given 編集モード中、When 「保存」ボタンを押下したとき、Then `PATCH /api/tasks/:id` に `{ description: <入力値> }` が送信され、成功後に編集モードが終了して更新後の説明が表示される

- **AC-5**: Given 編集モード中、When Ctrl+Enter キーを押したとき、Then 保存ボタン押下と同じ動作で保存が実行される

- **AC-6**: Given 編集モード中、When 「キャンセル」ボタンを押下したとき、Then 編集モードが終了し、変更前の説明（または空状態）に戻る。API は呼び出されない

- **AC-7**: Given 編集モード中、When Escape キーを押したとき、Then キャンセルボタン押下と同じ動作で編集が破棄される

- **AC-8**: Given 保存リクエストが進行中のとき、When テキストエリアと保存・キャンセルボタンを確認したとき、Then いずれも disabled 状態になっている

- **AC-9**: Given API がエラーを返したとき（例: 500）、When 保存を試みたとき、Then 編集モードを維持したまま説明エリア内にエラーメッセージが表示される

## エッジケース

- 説明を空文字列に変更して保存した場合: API には空文字列（`""`）を送信し、保存後は説明エリアをプレースホルダー表示に戻す
- 説明が変更なしの状態で保存した場合: API を呼び出さず、そのまま編集モードを終了する（不要なリクエストを避ける）
- 非常に長いテキスト（例: 10,000文字超）を入力した場合: テキストエリアは縦方向にスクロール可能であること（高さの上限を設ける）
- タスクがエージェントによって処理中（`column === "in-progress"` かつ `progress > 0`）の場合: 編集自体は禁止しないが、上書き保存が競合する可能性を考慮してユーザーに操作を許可する（競合制御は対象外）

## 非機能要件

- 既存のタイトル編集・サブタスク編集と同一の視覚スタイルを踏襲する（Tailwind CSS クラス・ボタンデザインを統一する）
- ダークモード対応: 説明エリア・テキストエリアとも既存の `dark:` クラスパターンに従う
