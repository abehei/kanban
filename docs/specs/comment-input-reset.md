# コメント入力欄のタスク切り替え時リセット

## 背景

TaskDetail パネルでコメントを入力中に別のタスクカードをクリックすると、入力途中のテキストが新しいタスクのコメント入力欄にそのまま残る。これはユーザーが意図しない誤送信や混乱を招くため、タスク切り替え時に入力欄を確実にリセットする必要がある。

## 対象範囲

### やること (In scope)
- タスクカードを切り替えたとき、コメント入力欄(本文テキストエリア)を空にリセットする
- タスクカードを切り替えたとき、投稿者名入力欄もデフォルト値にリセットする
- 送信中(isSubmitting)状態もリセットする

### やらないこと (Out of scope)
- 入力途中の内容を一時保存・復元する機能
- 「入力内容が失われます」等の確認ダイアログの表示
- コメント一覧(既投稿コメント)の表示内容には影響しない
- TaskDetail 内の他の入力欄(タイトル編集、サブタスク編集)のリセット挙動は変更しない

## 受け入れ基準

- **AC-1**: Given タスクAのコメント入力欄に「未送信のテキスト」を入力した状態で、When 別のタスクBのカードをクリックして TaskDetail を切り替えたとき、Then タスクBのコメント入力欄(テキストエリア)は空の状態で表示される

- **AC-2**: Given タスクAのコメント入力欄に文字を入力した状態で、When 同じタスクAのカードを再度クリックして TaskDetail を開き直したとき、Then コメント入力欄は空の状態で表示される（同一タスクでも再マウント時はリセットされる）

- **AC-3**: Given タスクAのコメントを送信完了した直後に、When タスクBに切り替えてから再びタスクAに戻ったとき、Then タスクAのコメント入力欄は空の状態で表示される

- **AC-4**: Given タスクAのコメント入力欄を空のまま(何も入力せず)で、When 別のタスクBに切り替えたとき、Then タスクBのコメント入力欄も空のまま表示される(既存の正常動作を壊さない)

- **AC-5**: Given タスクAで入力途中のコメントがある状態で、When タスクBに切り替えた後、Then タスクBのコメント一覧にはタスクB固有のコメントが正しく表示される(コメント一覧が混在しない)

## エッジケース

- タスクAのコメント送信中(isSubmitting=true)に別のタスクBに切り替えた場合、タスクBの入力欄は isSubmitting=false かつ inputText="" で初期化される
- 同一の `taskId` を持つカードが複数存在する場合（サブタスクなど）でも、切り替えのたびに入力欄がリセットされること
- 非常に素早く複数のカードを連続してクリックした場合でも、最後に表示されたタスクのコメント入力欄が空であること
- `taskId` の変化に追従するリセット処理は、コメント一覧の再フェッチと競合しないこと

## 非機能要件

- リセット処理は入力時のレイテンシに影響を与えない(同期的に完了すること)
- 既存の Cmd/Ctrl+Enter によるコメント送信ショートカットの挙動を壊さないこと
